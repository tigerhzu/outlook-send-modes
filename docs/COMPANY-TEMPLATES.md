# 統一範本卡片

更新：2026-11-15（Asia/Taipei）。

首頁只有一組卡片：加班、居家、居家申請（附當日工作清單）、內部 IT 需求／權限申請。已移除獨立的公司範本表單、即時預覽與插入流程。

## 使用方式

1. 點卡片「套用」，將收件者、主旨與預填範本放入目前草稿。
2. 直接在 Outlook 補填主旨日期、原因、工作內容等文字。工作清單沿用四列預設。
3. 需要變更往後的預設時，點卡片鉛筆，使用同一個 To／CC、主旨、內文編輯器，按 Save。
4. 既有收件者或主旨將被取代、或切換模板時，沿用同一個確認視窗。完成後自行檢查及寄出。

## 實作與升級

- 四份原始 HTML 與 JSON 仍為預設內容來源，先帶入 default 與展開工作列，再轉成一般 Mode；不再保留另一套表單／草稿寫入流程。
- 加班、居家以新版來源的內容、主旨與收件者為準；原有 overtime／remote ID 沿用。其餘自訂模式、常用聯絡人及簽章保留。
- 本機設定與舊備份在載入／匯入時升級；Save 才寫入，仍保留並行更新衝突檢查。presetRevision 記錄一次性升級，後續修改或刪除不會在重開後被預設覆蓋／補回。
- 四張卡片及自訂模式共用 ApplyController.apply、設定備份與 sendModesTemplateV1 草稿追蹤。To／CC 使用完整名單替換、跨欄去重，BCC 不動。
- 同一模板再次套用保留 Outlook 內的手動修改；切換模板或修改預設後，經確認只替換可辨識的模板區塊，保留其他內文、簽名與回覆歷史。
- 舊草稿只有一個公司模板追蹤時，從 sendModesCompanyV1 讀取並接入共用流程；成功寫入時移除舊屬性。若兩套舊追蹤同時存在、標記遺失／重複、只有標記卻無追蹤資料，或舊公司插入尚未確認完成，停止操作以保留原稿。
- 新版表格的深藍表頭、白字、留白、格線及既有 table 屬性經共用 sanitizer 保留，套用時仍使用共用的區塊限定樣式。
- Outlook 在替換內文或後續儲存時可能重新配置簽名圖片 CID。套用前先透過目前草稿的 Office 附件 API 取得圖片內容指紋，再核對新 CID 的圖片資料；確認相同才繼續。指紋僅存於單次操作記憶體，不改寫簽名圖片、不加入附件、不保存到設定。讀不到或圖片資料不同仍停止。
- 只操作目前草稿，不寄信、不加入 Graph 驗證。

## 驗證範圍

單元測試涵蓋來源內容與預設收件者、一次性設定升級、自訂資料保留、刪除後不重建、四份範本與自訂模式共用區塊、重複套用保留補字、舊草稿追蹤相容及安全停止。

Playwright 使用 Office.js mock，驗證四卡片、共用編輯器、套用／切換、內文補字、設定保存與重新開啟、舊備份升級，以及 320px／960px 版面。這些模擬測試與實機驗證分開記錄。2026-11-15 已另外在使用者開啟的新版 Outlook 草稿中，透過實際 Office.js 完成四份範本切換、To／CC／主旨回讀，以及簽名文字／連結／圖片資料保留驗證；最後切回居家，未寄信。詳細範圍見 [驗證報告](VERIFICATION.md)。

原 manifest 與 AppId 未改。若本機 HTTPS 服務已運行，關閉後重新開啟 Outlook 工作窗格即可載入。安裝與部署見 [INSTALL.md](INSTALL.md)。
