# Outlook 實機驗收

四個新公司範本的逐項驗收見 [COMPANY-TEMPLATES.md](COMPANY-TEMPLATES.md)。本次自動化與瀏覽器比對已通過，但新版 Windows、傳統 Windows、網頁版插入及手機收信都待實機驗證；以下為舊自訂模式的驗收紀錄，不代表新範本已通過。

公司版必須分別在 **Windows 新版 Outlook** 與 **Outlook for Mac** 完成下方跨平台驗收；Windows 傳統版與網頁版另記相容性結果。自動化的 Office.js mock、Playwright 瀏覽器測試、HTTPS 頁面預覽及 manifest 驗證都不能代替實機驗收。

## 自動化與實機的界線

- 型別檢查／建置：確認 TypeScript 與打包流程可執行，不能證明租戶允許側載。
- Manifest 驗證：確認宣告／結構合法，不能證明目前帳號與 Outlook 版本已載入命令。
- 單元及整合 mock：確認去重、儲存、草稿合併、確認及失敗處理邏輯，不能完整模擬 Outlook 對 HTML 的重寫。
- Playwright：確認工作窗格操作、模式儲存及 UI 行為，測試所用草稿是 Office.js mock，不是真實信箱。
- 實機 Outlook：必須確認宿主 HTML 標記保留、回覆 bodyMode、簽名圖片、草稿自訂屬性及不同草稿切換。若無法定位模板，程式採停止修改的保守行為。
